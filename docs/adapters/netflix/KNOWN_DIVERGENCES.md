# netflix 口径与已知分歧

本文件记录 `recap import <导出目录> --source netflix` 的计数口径, 以及我们的数字与
Netflix 自己的「观看活动」为什么会不一样。

数据来源: 账户导出里的 `ViewingActivity.csv`。一个家庭可能有多份 (每个档案一份,
放在不同子目录); 默认**合并成一个源**, 报告只说「已合并 N 个档案」, 不写档案名。

## 我们选的口径

| 规则 | 取值 | 理由 |
|---|---|---|
| 预告 / 回顾 / 钩子 | `Supplemental Video Type ∈ {HOOK, RECAP, TRAILER}` 排除 | 它们不是一次观看; 平台自己的统计也不计 |
| 自动播放预览 | `Duration <= 2 秒` 排除 | 预览行的常见值是 1 秒; 2 秒归入同一类, 边界写死可解释 |
| 续播重复 | `(profile_hash, title, start_time)` 保留**最大时长** | 同一集可能有多行; 先到先得会留下 2 分钟的那条 |
| 档案 | 默认合并, 不按档案拆分 | 产品讲的是「这一年」, 不是「谁看了什么」; 档案名不进任何产物 |
| `Profile Name` | 只取 sha256 前 16 位参与去重键 | 明文不进 `events`、`meta_json`、`flags`、`insights.json`、HTML |
| 时区 | `tz_offset_min = None`, 本地时间由工作区 `--tz` 决定 | `Start Time` 无偏移; 写成 0 会把小时分布锁死在 UTC |
| 时长 | `HH:MM:SS` -> 秒; 解析失败计跳过 | 不猜「大概是几分钟」 |
| 剧名 | `title` 存原串; `subtitle` 存**剧名**; 季进 `category`; 集名进 `meta.episode` | 见下方「为什么 subtitle 是剧名」 |

### 为什么 `subtitle` 是剧名, 不是季/集

任务书的字段表写的是「`subtitle` 存解析出的季/集」, 但集中度检测器取
`COALESCE(subtitle, title)` 做实体。把 `Season 6` 放进 `subtitle`, 「出现最多的项目」
会变成「出现最多的季」, 与 `entity_kind = show` 直接矛盾; 把整条 `title` 当实体,
又会按集拆开, 剧集永远进不了榜。所以实体列放剧名, 季与集分别进 `category` 与
`meta.episode` —— 字段与结构未动, 只是同一列承载了正确的粒度。

`Title` 的解析规则: 只认尾部 `: "集名"` 与倒数第二段的季标签
(`Season N` / `Limited Series` / `Part N` / `Volume N` / `Book N`)。认不出季标签时
剧名保持原样、季为 `None` —— 不从标题结构猜口味, 也不猜季数。
`Star Trek: Discovery: Season 1: "..."` 这类「剧名自带冒号」的情况按最后一段切分,
不会把剧名截断。

## 与平台「观看活动」的分歧

| 分歧 | 为什么合法 | 我们选哪边 |
|---|---|---|
| 总数比「我以为看了多少」少 | 预告/回顾/钩子、1–2 秒预览、续播重复行都被排除了 | 只计有效观看; 逐文件账写明每条跳过原因 |
| 同一集出现两行、时长不同 | 续播会追加一行, 或中途退出后重看 | 保留最大时长, 一行一条 |
| 本地日期与平台显示差一天 | `Start Time` 是 UTC, 平台按账号时区显示 | 用工作区 `--tz` 换算; 换时区会改变深夜占比 |
| 档案名不可见 | 隐私: 名字是 PII | 只保留哈希, 报告只说档案数 |
| 本地化表头读不了 | 目前只认英文列名 | 报错指名缺失的列; 不猜列名映射 |

## 编码矩阵 (由测试实测)

`tests/unit/test_adapter_netflix_encoding.py` 逐格断言; 下表是它的实测结果。

| 输入 | 结果 | 原因 / 说明 |
|---|---|---|
| UTF-8 无 BOM | 解析 1 | 首选编码 |
| UTF-8 带 BOM | 解析 1 | `utf-8-sig` 去掉 BOM, 不污染第一列列名 |
| cp1252 (重音片名 `Amélie`) | 解析 1 | 第二候选; 不乱码 |
| CRLF 行尾 | 解析 1 | `csv` 模块按行处理 |
| 字段内嵌逗号与引号 | 解析 1 | 原串一字不差 |
| 单个坏字节 `0x81` | 跳过 1 | `bad_encoding`: 两种编码都不接受, 只跳过该行 |
| 孤立 NUL 行 | 跳过 1 | `bad_row`: 列数不符; 不崩掉整份文件 |
| 空文件 | 整份跳过 | 记为「空文件」, 其余文件照常导入 |
| 超长字段 (> 128 KB) | 整份跳过 | 记为「CSV 结构错误」 |
| 缺必需列 | 报错 | 指名文件与列, 不猜 |

## 已知 caveat

- **`Start Time` 按 UTC 解读。** 导出不带偏移; 我们不猜「大概是本地时间」。用
  `tz.split_utc_and_offset()` 归一, 返回 `(ts_utc, None)`。平台显示的是账号时区,
  两者在跨日边界上会差一天。
- **只支持英文表头。** 本地化导出 (例如中文列名) 会以「缺少必需列」失败, 并点名
  期望的列。
- **预览阈值是 2 秒。** 如果某些地区的自动播放预览是 3–5 秒, 它们会被计入观看。
  这是已知的保守选择: 宁可多算几条短观看, 也不误删真实的长观看。

## 换口径的开关

没有 CLI 开关。要改预览阈值或 supplemental 集合, 改
`src/recapkits/adapters/netflix_parse.py` 的 `PREVIEW_MAX_S` /
`EXCLUDED_SUPPLEMENTAL`, 同时更新本文件、编码矩阵与
`tests/unit/test_adapter_netflix.py` 的边界用例。
